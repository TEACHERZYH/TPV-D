## 一、工程结构与系统架构概览

### 1.1 总体架构设计

TPV-D（Task-Process-Verification-Discrepancy）实验教学评价平台针对 AIGC（生成式人工智能）高频介入下的工程教育痛点，构建了“**自动化技术指标评测 + 过程行为捕获 + 现场机试验证 + 异常倒挂差异诊断**”的人机协同评价闭环。系统在软件架构上划分为清晰的四层体系：

```
+-----------------------------------------------------------------------------------+
|                        表示层 / 交互终端 (Presentation Layer)                      |
|    - 教师人机复核工作台        - 班级全景仪表盘        - 学生画像与靶向诊断视图       |
+-----------------------------------------------------------------------------------+
                                         │  HTTP / RESTful API / Jinja2 SSR
+-----------------------------------------------------------------------------------+
|                        应用服务层 (Application Service Layer)                      |
|    - FastAPI 高性能 Web 框架 (tpvd_platform/web_app/app.py)                         |
|    - 路由分发器、模板渲染引擎、REST API 端点控制器、异常处理机制                     |
+-----------------------------------------------------------------------------------+
                                         │  Internal Service Calls
+-----------------------------------------------------------------------------------+
|                        领域模型与核心算法层 (Domain & Algorithm Layer)              |
|    - 达成度计算 (式1/式2)     - 异常倒挂检测 (式3)       - 工时优化评估 (式4)       |
|    - 自动化量化评分引擎       - 数字信号处理 (DSP)       - 无线协议与 ARQ 仿真     |
+-----------------------------------------------------------------------------------+
                                         │  CRUD & File I/O
+-----------------------------------------------------------------------------------+
|                        数据与持久化层 (Persistence & Data Layer)                   |
|    - 内存/JSON 数据仓库       - 实证全息数据集 (N=95)   - 仿真测试样本库 (CSV/BIN)  |
+-----------------------------------------------------------------------------------+
```

### 1.4 技术选型与设计原则

1. **零外部服务依赖（Zero-Dependency Footprint）**：采用轻量级文件数据库（JSON File Store），免除 MySQL/PostgreSQL 安装配置负担，可在任意教学用机、虚拟机或学生电脑上一键部署启动。
2. **双模式导入兼容（Dual-Mode Import Compatibility）**：在所有核心算法模块中加入环境自适应容错：
   ```python
   try:
       from .models import Student, ScoreRecord
   except ImportError:
       from models import Student, ScoreRecord
   ```
   使得各脚本既能作为整体工程包引入，也能由师生在终端中作为单文件脚本独立执行调试。
3. **松耦合模块化（High Cohesion & Low Coupling）**：算法层（`scripts`）完全独立于 Web 框架，便于在不同实验场景、不同评测系统（如脚本打分、在线评测机 OJ、本地 GUI）中快速复用。

## 二、核心业务模块与技术特性实现细节

### 2.1 数据分析与解调算法模块 (`scripts/`)

该模块对应电子信息专业综合实训的核心工程任务，涵盖从传感器前级调理、模数转换动态性能评估，到无线报文解调校验的全链路。

#### 2.1.1 传感器静态校准与端点非线性度评估 (`sensor_calibration.py`)
- **工程背景**：热敏/光敏传感器在宽温区工况下存在非线性响应，需通过多点校准拟合并评估其端点线性度。
- **核心算法**：
  1. **一元线性回归拟合**：利用最小二乘法计算理论端点连线斜率 $k$ 与截距 $b$：
     $$k = \frac{\sum_{i=1}^n (x_i - \bar{x})(y_i - \bar{y})}{\sum_{i=1}^n (x_i - \bar{x})^2}, \quad b = \bar{y} - k \cdot \bar{x}$$
  2. **端点平移与绝对残差**：计算实测输出与理论拟合直线之间的最大偏差：
     $$\Delta y_{max} = \max_{1 \le i \le n} \left| y_i - (k x_i + b) \right|$$
  3. **端点非线性度误差**：以满量程输出（Full Scale, $Y_{FS} = y_{max} - y_{min}$）为基准评估系统误差：
     $$\delta_L = \frac{\Delta y_{max}}{Y_{FS}} \times 100\%$$
- **技术指标约束**：实训要求校准后系统的非线性度指标须满足 $\delta_L < 1.5\%$。

#### 2.1.2 ADC 动态性能分析与 Q15 定点 IIR 滤波 (`adc_dsp_analyzer.py`)
- **工程背景**：高速交替采样 ADC 系统易受时钟抖动、量化噪声与谐波失真影响，需进行全带宽动态特性测试及定点滤波优化。
- **核心算法**：
  1. **加汉宁窗频域分析**：对采样时域信号 $x[n]$ 加 Hanning 窗后进行快速傅里叶变换（FFT），有效抑制频谱泄漏；
  2. **信纳比（SINAD）与有效位数（ENOB）求解**：
     $$\text{SINAD} = 10 \log_{10} \left( \frac{P_{signal}}{P_{noise} + P_{harmonics}} \right) \quad (\text{dB})$$
     $$\text{ENOB} = \frac{\text{SINAD} - 1.76}{6.02} \quad (\text{bits})$$
  3. **Q15 定点化级联双二阶节（Biquad）IIR 滤波器仿真**：
     - 将浮点 IIR 滤波系数按 $C_{Q15} = \text{round}(C_{float} \times 32768)$ 映射至 16 位有符号整型；
     - 采用 Direct Form II 转置结构级联实现 4 阶低通滤波；
     - 包含定点饱和运算（Saturation Arithmetic）与溢出保护，仿真运算群时延 $\tau < 2.0\text{ ms}$。
- **技术指标约束**：要求系统实测动态指标达到 $\text{ENOB} \ge 11.2\text{ bits}$，滤波延迟严格受控。

#### 2.1.3 无线传感器报文解析与停等 ARQ 信道仿真 (`wireless_protocol_parser.py`)
- **工程背景**：物联网节点通信需在信道噪声环境下保证报文帧同步、数据完整性与可靠交付。
- **核心算法**：
  1. **双字节前导码帧同步**：以 `0xAA 0x55` 构筑帧同步头，采用滑动状态机检索帧边界，规避字节对齐错误；
  2. **自定义大端报文格式**：
     `[Preamble: 2B][DeviceID: 2B][SeqNum: 1B][Length: 1B][Payload: NB][CRC-16: 2B]`
  3. **CRC-16-CCITT 校验引擎**：采用国际标准生成多项式 $G(x) = x^{16} + x^{12} + x^5 + 1$（十六进制 `0x1021`），初始值 `0xFFFF`，保证突发差错检出率；
  4. **Stop-and-Wait ARQ 信道状态统计**：仿真高斯白噪声信道下的丢包、重传与超时计时器，统计吞吐率、丢包率与往返时延（RTT）。
- **技术指标约束**：要求通信丢包率 $< 2.0\%$，重传机制下的端到端平均交付延迟 $< 50\text{ ms}$。

#### 2.1.4 实训成果自动化量化评分引擎 (`automated_evaluator.py`)
- **工程背景**：自动化评价任务指标达成情况，为 $T$（Task）维度提供客观、可复现的基准分。
- **打分量规与权重分配**：
  - **T1 传感器线性标定**（满分 20 分）：拟合优度 $R^2 \ge 0.999$ 得 10 分，端点非线性度 $\delta_L < 1.5\%$ 得 10 分；
  - **T2 ADC 动态频谱评估**（满分 20 分）：$\text{ENOB} \ge 11.2\text{ bits}$ 得 12 分，$\text{SNR} \ge 68.0\text{ dB}$ 得 8 分；
  - **T3 定点数字滤波性能**（满分 20 分）：通带纹波 $< 0.5\text{ dB}$ 得 8 分，阻带衰减 $> 40\text{ dB}$ 得 8 分，处理延时 $< 2.0\text{ ms}$ 得 4 分；
  - **T4 通信帧解析与 CRC**（满分 20 分）：帧头捕获率 $100\%$ 得 8 分，CRC 检错正确率 $100\%$ 得 12 分；
  - **T5 ARQ 传输可靠性**（满分 20 分）：报文丢包率 $< 2.0\%$ 得 10 分，重传延时 $< 50\text{ ms}$ 得 10 分。
- **总评输出**：生成自动化得分 $T_i \in [0, 100]$ 及细项得分字典，直接对齐课程目标（CLO）。

#### 2.1.5 真实工况测试数据生成器 (`demo_data_generator.py`)
- 自动生成合规的多循环标定测试样例文本（`sensor_cal_sample.csv`）；
- 自动合成含指定基波与谐波的高保真 ADC 采样二进制流（`adc_raw_sample.bin`）；
- 自动打包包含正常帧、误码帧与超长载荷帧的无线测试用例集（`wireless_frames_sample.json`）。

### 2.2 教学评价与核心数学模型模块 (`platform_core/`)

#### 2.2.1 基础实体与考核维度建模 (`models.py`)
系统定义了紧密契合工程教育认证标准的领域实体模型：
- **`CourseLearningOutcome` (CLO)**：课程培养目标，映射电子信息工程毕业要求指标点：
  - **CT1**：硬件调理与接口设计能力（支撑毕业要求 1：工程知识）；
  - **CT2**：数字信号处理与频谱分析能力（支撑毕业要求 2：问题分析）；
  - **CT3**：嵌入式通信与协议实现能力（支撑毕业要求 3：设计/开发解决方案）；
  - **CT4**：复杂系统集成与工程调试能力（支撑毕业要求 5：现代工具使用）。
- **`ScoreRecord`**：学生考核全息记录，涵盖 TPV-D 四维观测向量：
  - $T$：自动化任务指标得分（Task Performance Score，0~100）；
  - $P$：过程提交与版本演进得分（Process Engagement Score，0~100）；
  - $V_I$：现场独立闭卷机试验证得分（Individual In-lab Verification Score，0~100）；
  - $V_{AI}$：现场人机协同探索机试得分（AI-Assisted In-lab Verification Score，0~100）；
  - $D_i$：倒挂偏离度（Discrepancy Index）；
  - $R_i$：异常倒挂预警标志（Risk Flag，布尔型）。

#### 2.2.2 个体与班级达成度计算引擎 (`score_calculator.py`)


1. **个体在具体课程目标上的达成度（论文公式 1）**：
   $$S_i(c) = \sum_{j} w_{j,c} \cdot S_{i,j}$$
   式中，$S_i(c)$ 表示第 $i$ 位学生在课程目标 $c$ 上的达成度得分；$w_{j,c}$ 为考核评价环节 $j$ 支撑课程目标 $c$ 的权重系数（满足 $\sum_j w_{j,c} = 1.0$）；$S_{i,j}$ 为该学生在评价环节 $j$ 的标准化得分（折算为 0~1 区间）。

2. **教学班群体综合达成度（论文公式 2）**：
   $$A_c = \frac{1}{N} \sum_{i=1}^N S_i(c)$$
   式中，$N$ 为教学班总人数；$A_c$ 为全班在课程目标 $c$ 上的平均达成度。工程教育认证通常要求 $A_c \ge 0.70$ 方为达成合格。

#### 2.2.3 异常倒挂筛查与人机协同增效模型 (`discrepancy_detector.py`)
该模块是 TPV-D 框架解决“AIGC 代劳虚假高分”的核心抓手：

1. **异常倒挂偏离度定义（论文公式 3）**：
   $$D_i = T_i - V_{I,i}$$
   $$R_i = \mathbb{I}\left( T_i \ge 85 \land V_{I,i} < 60 \right)$$
   式中，$\mathbb{I}(\cdot)$ 为指示函数。当且仅当学生课后提交的实训技术指标达到优秀（$T_i \ge 85$ 分），但脱离外部工具的现场闭卷机试出现不及格（$V_{I,i} < 60$ 分）时，$R_i$ 触发警报（置为 1），被系统强制标记为**异常倒挂高危样本**。

2. **人机协同复核工时优化率（论文公式 4）**：
   $$L = \frac{N_{total} - (N_{flagged} + N_{random})}{N_{total}} \times 100\%$$
   在实证班级（$N=95$）中，自动化系统筛查出 $N_{flagged} = 14$ 名倒挂学生，叠加 $N_{random} = 8$ 名随机质控抽检样本，教师仅需深入介入复核 22 人，工时节约率达到：
   $$L = \frac{95 - (14 + 8)}{95} \times 100\% = 76.8\%$$
   大幅减轻了教师全面逐一人工答辩的批阅负担。

#### 2.2.4 95 名学生实证全息数据集与持久化服务 (`seed_data.py`, `database.py`)
- **真实数据映射**：预置了与论文完全一致的 95 名电子信息专业本科生实操数据集。
- **实证全景结果还原**：
  - 班级总人数：$N = 95$；
  - 自动化触发倒挂预警人数：14 人；
  - 质控随机抽检人数：8 人；
  - 教师复核介入总数：22 人；
  - 经教师深入审查后，最终裁定存在 AIGC 严重代劳、缺乏独立工程理解的样本：21 人；
  - 靶向变式实验重测通过人数：12 人；
  - 班级四个课程目标最终达成度评价：
    $$\text{CT1} = 0.79, \quad \text{CT2} = 0.81, \quad \text{CT3} = 0.82, \quad \text{CT4} = 0.77$$
    全面达到且优于工程教育认证要求的 0.70 达标阈值。

#### 2.3.1 班级综合达成度全景看板 (Dashboard)
- **路由**：`GET /`
- **核心组件**：

  2. **课程目标（CT1~CT4）达成度雷达图**：对比各目标实际达成度与 0.70 达标基准线；
  3. **$T - V_I$ 倒挂散点图**：横轴为独立验证分 $V_I$，纵轴为作业自动化分 $T$。右上角绿色区域为优良稳定区，左上角红色阴影区域为典型高危倒挂区（$T \ge 85, V_I < 60$），视觉穿透力强。

#### 2.3.2 教师端人机协同复核工作台 (Teacher Desk)
- **路由**：`GET /teacher`
- **业务逻辑**：
  - 列表优先展示 $R_i = \text{True}$ 的高危学生，并按倒挂差值 $D_i = T_i - V_{I,i}$ 降序排列；
  - 标签化展示抽检来源（“系统倒挂告警”或“常规随机抽检”）；
  - 提供一键跳转至专属复核页面的快捷入口。

#### 2.3.3 学生个体画像与薄弱项诊断视图 (Student View)
- **路由**：`GET /student/{student_id}`
- **业务逻辑**：
  - 面向学生提供去隐私化的成长诊断报告；
  - 呈现学生在 CT1~CT4 上的达成雷达曲线；
  - 针对低于 0.70 的薄弱目标（例如 CT3 协议解析与可靠通信），自动生成靶向变式实验强化建议。

#### 2.3.4 人机仲裁与变式测试闭环流转
- **路由**：`GET /review/{student_id}`, `POST /review/{student_id}`
- **业务流转**：
  1. 教师进入复核详情页，核对学生的代码版本演进日志、过程提问记录与闭卷测试实况；
  2. 教师下发带有随机参数变式的补测任务（如更换 CRC 初始初值或修改数字滤波器截止频率）；
  3. 教师录入最终仲裁结论（“核准通过”、“认定借力过度-扣减分数”或“变式补测合格”），系统自动重新核算该生的综合达成度得分。

## 四、工程扩展与二次开发指南

1. **接入新的实训模块**：
   在 `scripts/` 中新增针对新外设或算法的分析脚本（如 `fpga_ddr_analyzer.py` 或 `can_bus_parser.py`），并在 `automated_evaluator.py` 的测试套件中添加对应子项的量化判定函数。
2. **自定义课程目标映射权重矩阵**：
   在 `platform_core/models.py` 中修改 `CLO_WEIGHT_MAP` 字典，自由调整各实验任务在不同指标点上的分配权重（如增强某一任务对“复杂工程问题”的支撑占比）。
3. **集成高校校园统一身份认证 (OAuth2 / CAS)**：
   在 `web_app/app.py` 中接入标准 OAuth2 鉴权中间件，实现从教务系统一键单点登录，自动拉取真实班级学生学号与名册。
4. **导出工程教育认证自评附件报告**：
   可调用 `platform_core/score_calculator.py` 中的统计数据，结合本地 `python-docx` 库一键批量导出符合中国工程教育专业认证协会（CEEAA）标准规范的《课程达成度分析与持续改进评价报告》。
